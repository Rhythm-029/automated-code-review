# Automated Code Review Comment Generation Using Large Language Models

A BTech capstone project focused on automatically generating accurate, actionable, and screened code review comments on GitHub Pull Request code diffs using Large Language Models (LLMs).

## Project Overview

Code review is a critical stage in the software development lifecycle, ensuring code quality, security, and maintainability. However, manual code review requires substantial developer time and cognitive effort. 

This project explores using Large Language Models (LLMs) to automatically generate candidate review comments for pull request code diffs. To prevent incorrect or misleading suggestions, the system incorporates a dedicated **hallucination screening pipeline** before any comment is surfaced.

## System Architecture (Planned)

The planned system pipeline operates as follows:

```text
GitHub PR Code Diff
       │
       ▼
LLM Candidate Comment Generation
       │
       ▼
Hallucination Screening Pipeline
  ├── 1. Symbol Grounding (Checks entity existence in diff/context)
  └── 2. Natural Language Inference (DeBERTa-MNLI checks textual premise support)
       │
       ▼
Confidence Gate
  ├── Pass threshold ──► Emit Draft Comment (Clearly labeled as AI-generated)
  └── Fail threshold ──► Abstain (Do not post comment)
       │
       ▼
Human Reviewer (Makes final decision to accept, modify, or reject)
```

### High-Level Workflow
1. **Input**: GitHub Pull Request code diff along with surrounding file context.
2. **LLM Generation**: A fine-tuned LLM generates candidate review comments identifying potential bugs, code smells, or style improvements.
3. **Hallucination Screening**:
   - **Symbol Grounding**: Verifies whether code entities (variable names, functions, class names) mentioned in the comment exist within the diff or context.
   - **NLI (Natural Language Inference)**: Uses a DeBERTa-MNLI model to verify if the code context logically entails the generated claim.
4. **Confidence Gate**: Evaluates scores from symbol grounding and NLI. If confidence is high, the comment is emitted; otherwise, the system abstains from making a comment.
5. **Human Review**: The final decision always rests with the human developer/reviewer.

## Future Deployment Roadmap

The target deployment architecture for the project is designed for lightweight, low-cost execution:

- **Model Optimization**: 4-bit quantization of fine-tuned LLMs into `GGUF` format.
- **Inference Runtime**: `llama.cpp` serving optimized GGUF weights on CPU hardware.
- **API Wrapper**: A lightweight `FastAPI` service bridging inference request endpoints.
- **CI/CD Integration**: A custom `GitHub Action` triggered on Pull Requests to post AI-generated draft comments for human review.

*Note: Deployment components represent the planned technical path and are currently under active design and development.*

## Live Runnable MVP

A complete, locally runnable MVP is now implemented with a full-stack architecture:

- **Frontend**: React + Vite + TypeScript + modern dark theme developer UI (`frontend/`)
- **Backend**: FastAPI REST service with Pydantic validation, CORS, and SQLite/JSON persistence (`backend/`)
- **Review Engines**:
  - `ollama` (Primary / Default): 100% free, local inference using **`qwen2.5-coder:7b`** via Ollama (`http://localhost:11434`). Requires zero paid API keys.
  - `demo`: Heuristic rule-based fallback engine with explicit `⚠️ DEMO MODE — NOT GENERATED BY A REAL MODEL` labeling.
  - `openai` / `anthropic`: Optional cloud LLMs.
  - `finetuned`: Hugging Face sequence-to-sequence model (`Salesforce/codet5-small`).
- **ML Utilities**:
  - Dataset leakage audit & cleaning: [`ml/audit_dataset.py`](ml/audit_dataset.py), [`ml/prepare_dataset.py`](ml/prepare_dataset.py)
  - Fine-tuning pipeline with smoke test: [`ml/train.py`](ml/train.py)
  - Benchmark evaluation & qualitative reporting: [`ml/evaluate.py`](ml/evaluate.py)
  - CLI inference tool: [`ml/infer.py`](ml/infer.py)

## Quickstart Guide

### Prerequisites
- Python 3.10+ (tested with Python 3.13)
- Node.js 18+ & npm
- [Ollama](https://ollama.com/) running locally with model `qwen2.5-coder:7b` (`ollama run qwen2.5-coder:7b`)

### 1. Environment Configuration

Copy the example environment configuration:
```bash
cp .env.example .env
```

Default configuration in `.env` uses local Ollama without requiring any API keys:
- `REVIEW_ENGINE=ollama`
- `OLLAMA_BASE_URL=http://localhost:11434`
- `OLLAMA_MODEL=qwen2.5-coder:7b`
- `OLLAMA_TIMEOUT=120`

### 2. Start the Backend

```bash
# Using the startup script:
./start_backend.sh

# Or directly:
uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload
```
The backend API is accessible at `http://127.0.0.1:8000`. Interactive API documentation (Swagger UI) is available at `http://127.0.0.1:8000/docs`.

### 3. Start the Frontend

```bash
# Using the startup script:
./start_frontend.sh

# Or directly:
cd frontend
npm run dev -- --host 127.0.0.1 --port 5173
```
Open your browser at `http://localhost:5173`.

## Machine Learning & Dataset Tools

### Dataset Inspection and Leakage Audit
To inspect record counts, duplicate IDs, exact patch-comment duplicates, and cross-split test leakage:
```bash
python ml/audit_dataset.py --dataset-dir dataset
```

### Dataset Preparation (Deduplication & Leakage Removal)
Creates a clean, non-destructive manifest with cross-split duplicates removed from evaluation splits:
```bash
python ml/prepare_dataset.py --input-dir dataset --output-dir dataset_clean
```

### Training Pipeline
Run a quick smoke-test on 100 examples to verify tokenizer and model pipelines:
```bash
python ml/train.py --smoke-test
```
Full fine-tuning on available hardware:
```bash
python ml/train.py --dataset-dir dataset --epochs 3 --batch-size 8
```

### Model Evaluation
Evaluate models with BLEU, ROUGE-L, exact match, and qualitative inspection reports:
```bash
python ml/evaluate.py --dataset-dir dataset --checkpoint models/codet5-finetuned --n-examples 100 --output reports/eval_results.json
```

### CLI Inference
Analyze code diffs directly from the terminal:
```bash
python ml/infer.py --patch "@@ -1,4 +1,7 @@
 def divide(a, b):
+    if b == 0:
+        return None
     return a / b"
```

## Security & Privacy Highlights

1. **Untrusted Code Handling**: Submitted code and diffs are strictly parsed as text; code is never executed locally.
2. **PII and Secret Redaction**: Configured email addresses, bearer tokens, and credentials are automatically redacted before any external model calls.
3. **Read-Only GitHub**: GitHub pull request analysis only fetches diffs. No automated write actions or review postings are performed.
4. **Explicit Demo Labelling**: When running in demo mode, every comment is clearly prefixed with `⚠️ DEMO MODE — NOT GENERATED BY A REAL MODEL`.
