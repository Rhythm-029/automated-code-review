# Dataset Plan: Microsoft CodeReviewer

## Dataset Overview

The project plans to utilize the publicly available **Microsoft CodeReviewer** dataset, a large-scale dataset collected from open-source GitHub pull requests designed specifically for code review automation tasks.

### Key Dataset Characteristics
- **Data Unit**: Code diff and review comment pairs (`diff-comment` pairs).
- **Language Coverage**: Spans **9 programming languages** (C, C++, C#, Java, JavaScript, Python, Go, Rust, TypeScript).
- **Target Task**: The dataset supports multiple sub-tasks; this project focuses specifically on the **Code Review Comment Generation** task (generating natural language review comments given a PR code diff hunk).

## Data Cleaning & Preprocessing Strategy (Planned)

Raw code review datasets collected from GitHub contain significant noise. The following cleaning pipeline is planned:

1. **Bot & Automated Account Removal**: Filter out comments generated by CI/CD bots (e.g., Dependabot, Codecov, SonarQube).
2. **Trivial Comment Filtering**: Exclude non-informative comments such as "LGTM", "looks good", "+1", "thanks", or simple formatting praise that do not provide actionable code review feedback.
3. **Duplicate & Template Removal**: Deduplicate identical diff-comment pairs caused by re-submitted PRs or standardized project issue templates.
4. **PII & Secret Sanitization**: Strip potential sensitive data, private emails, IP addresses, or hardcoded tokens using regex pattern matching.
5. **Length Constraints**: Filter out excessively long diffs or truncated comments that exceed context window limits.

## Data Splitting Strategy

To evaluate genuine generalization across unseen projects, the data split will adhere to a **repository-disjoint split strategy**:
- **Train Split**: Used exclusively for fine-tuning models.
- **Validation Split**: Used for hyperparameter selection and early stopping.
- **Test Split**: Contains pull requests from repositories strictly excluded from the training and validation sets.

> **Status Note**: The dataset acquisition and cleaning procedures outlined above represent the planned pipeline. No specific count of cleaned samples is claimed prior to executing the data processing scripts.
